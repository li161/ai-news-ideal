# AI 探索局：产品方案与路线图

## 1. 产品定义

**产品名：** AI 探索局  
**一句话：** 每天花 5 分钟，以轻松、有趣、可深入的方式发现 AI 世界的新变化。  
**核心体验：** Explore-first（探索优先）。  
**目标用户：** 普通 AI 工具使用者 + 开发者/技术爱好者。

不是传统 AI 新闻聚合器，也不是只面向开发者的 Harness 知识库。产品用探索体验降低发现门槛，用双层内容深度覆盖不同认知水平。

## 2. 用户与价值

### 普通用户
- 想知道 AI 最近有什么新鲜事，但不想读长篇技术文章。
- 需要生活化解释、实际例子和可体验入口。
- 核心价值：看得懂、愿意点开、每天有新发现。

### 技术用户
- 关注模型、Agent/Harness、工具生态、推理基础设施和开源项目。
- 需要版本、机制、架构取舍、代码/文档和原始来源。
- 核心价值：快速捕捉变化、建立技术联系、追到一手资料。

## 3. 产品原则

1. **探索先于信息密度：** 首屏只呈现少量精选线索，不堆新闻列表。
2. **双层解释：** 轻松看懂与深入研究共享同一事实记录，不维护两套互相矛盾的内容。
3. **来源优先：** 每条技术进展必须可追溯到官方公告、仓库、论文或可信的一手资料。
4. **事实与判断分离：** 日期/版本/发布内容是事实；影响分析是解释；未来趋势是判断。
5. **每天少而精：** 首页精选 3–5 条高价值发现，拒绝以数量制造活跃。
6. **积累而非刷 feed：** 收藏、探索足迹、主题地图和连续学习构成长期价值。
7. **不假装实时：** 静态种子数据、人工审核数据和自动采集数据必须明确区分。

## 4. 核心信息架构

### 首页：今日探索
- 今日主线：一句话讲清当天最值得关注的变化。
- 今日精选：3–5 条事件，标注日期、来源、主题。
- 惊喜探索：随机打开一条未读线索。
- 每日挑战：一道低门槛理解题。
- 我的足迹：已读、收藏、探索点数。

### 六个探索世界
1. 模型进化：模型能力、推理、多模态、训练。
2. Agent 与 Harness：Loop、状态、上下文、工具调用、Subagent、Runtime。
3. 工具与生态：MCP、Skills、插件、开发框架、开源项目。
4. 算力与基础设施：GPU、推理优化、成本、部署、沙箱。
5. 多模态创造：图像、视频、语音、3D、实时交互。
6. AI 落地与商业：行业应用、AI Native 产品、工作流和商业模式。

### 内容详情
- 发生了什么：普通用户可读的简明解释。
- 技术细节：版本、机制、架构与实现。
- 为什么值得关注：影响范围和工程意义。
- 原始资料：可访问的官方来源。
- 相关探索：同主题历史事件与概念。

### 个人探索记录
- 已读线索、收藏线索、探索点数。
- 后续可增加主题掌握度、连续探索天数和个人知识图谱。
- MVP 阶段数据保存在浏览器 localStorage，不承诺跨设备同步。

## 5. 内容模型

每条内容建议采用统一结构：

| 字段 | 含义 |
|---|---|
| id | 稳定唯一标识 |
| title | 探索标题 |
| category | 六大主题之一 |
| published_at | 事件真实发布日期 |
| discovered_at | 本站发现/收录日期 |
| source_name | 来源名称 |
| source_url | 原始资料链接 |
| source_type | 官方公告/仓库/论文/技术文档 |
| fact_summary | 可核验事实 |
| easy_explanation | 轻松模式解释 |
| deep_explanation | 深入模式解释 |
| why_it_matters | 影响与意义分析 |
| tags | 技术标签 |
| verification_status | 待核验/已核验/有争议 |
| freshness | 最新/近期/历史背景 |

## 6. 每日内容生产流程

目标流水线：

1. 采集：官方博客、Changelog、GitHub Releases、论文和项目仓库。
2. 去重：以 URL、项目、版本号和内容指纹合并重复事件。
3. 筛选：评估新颖性、影响范围、技术价值、可信度和用户兴趣。
4. 事实提取：保留发布日期、版本号、具体变化和原始链接。
5. 双层解读：生成普通用户解释与技术用户解释。
6. 关联：挂接六大主题、历史事件和相关概念。
7. 审核：核验原始来源，检查事实/推断是否混写。
8. 发布：生成每日精选与专题档案。

**关键约束：** LLM 只能辅助摘要、分类和解释，不能作为事实来源；缺少可访问原始来源的内容不得标记为“已核验”。

## 7. MVP 范围（当前静态站）

### 已实现
- Explore-first 首页与六大主题入口。
- 今日精选事件与来源链接。
- 轻松看懂/深入研究双模式。
- 随机探索入口。
- 详情弹层。
- 本地收藏、已读、探索点数。
- 每日挑战与即时反馈。
- 本地探索足迹。

### 尚未实现
- 自动抓取和定时更新。
- 后端内容库、管理审核台。
- 跨设备账号与云端同步。
- 真正的连续签到和历史日期归档。
- 全量专题内容与知识图谱。
- 用户自定义订阅和推送。

## 8. 技术演进建议

### 阶段 1：静态可体验 MVP
- GitHub Pages 托管。
- HTML/CSS/原生 JavaScript。
- 内容先内嵌，localStorage 保存个人行为。
- 重点验证首页探索体验、双层阅读和收藏是否有吸引力。

### 阶段 2：内容数据化
- 将内容从页面拆到 JSON。
- 增加内容 schema 校验、来源状态、日期归档。
- 增加搜索、主题筛选、时间线和相关内容。

### 阶段 3：自动情报流水线
- GitHub Actions 定时采集官方 RSS、GitHub Releases 和 Changelog。
- 规则去重、来源白名单、候选事件评分。
- LLM 生成双层解读草稿。
- 人工审核后发布 JSON，保留来源和审核状态。
- 失败时保留上一版有效内容，不发布空白日报。

### 阶段 4：个性化探索
- 账号与云端收藏。
- 按主题偏好调整精选排序。
- 知识路径、概念关联和学习挑战。
- 周报/月报与个人探索报告。

## 9. 内容质量与运营指标

北极星指标：**每周完成至少 3 次有效探索的活跃用户数。**

辅助指标：
- 首屏到详情的打开率。
- 单次有效探索完成率（打开详情 + 停留/交互）。
- 收藏率。
- 每日挑战完成率。
- 7 日回访率。
- 来源可访问率与核验通过率。
- 普通/深入模式切换比例。

避免只优化 PV、新闻条数和页面停留时长。
